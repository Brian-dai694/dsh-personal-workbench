# Amazon 测算：界面重排（v1.24，2026-10-31）

## 这次改的是"读起来费劲"，不是"功能缺"

测算页的功能层（成本口径、佣金固定 15%、容器查询断点、方案库对比）此前已经过几轮打磨。
本轮只动**呈现与信息层级**，四条原则：结论先于明细、单位贴着数字、口径可折叠、动作不抢主按钮。

## 具体改动

| 问题（改前） | 改法（改后） |
|---|---|
| 销售佣金字段里是**金额**（6.00），右边却固定写着 `15%` —— 同一格两套口径 | 只读金额按两位小数显示（`6.00`），不再挂 `%`；"固定 15% · 随售价自动计算"留在字段说明里 |
| `%` 后缀被 flex 推到 241px 输入框的最右边，离数字 200px | 后缀绝对定位到输入框**内部右缘**（`has-suffix` + `padding-right`），数字与单位成为一个整体 |
| 8 个指标一样大，等于没有重点 | 分两层：4 个**结论**（有效单件贡献 / 目标 ACOS CPC / 盈亏平衡 ACOS / 广告后利润）+ 小标题「核对明细」下的 4 个**核对数值**（安全值 / 成本合计 / 两个差值），字号小一档 |
| 「恢复默认值」被渲染成整行宽按钮，比主按钮还重 | 收进输入卡底部的动作行：保存状态在左、按钮在右；恢复默认值是破坏性动作，本就不该最显眼 |
| 计算口径是一大段灰字，压在结论下面 | 收进原生 `<details>`「计算口径」，默认折叠；口径留着（它是结论可信度的一部分），但不再挡在结论前面 |
| 顶部按钮写「保存参数」，状态文案写「参数已保存在本机浏览器」 | 按钮改「保存到本机」，状态改「已保存在本机浏览器 / 参数尚未保存」——同一个动作只有一种说法 |

## 为什么用 `<details>` 而不是自建折叠组件

要的是"能查到"，不是"能交互"。原生 `details/summary` 键盘可达、有内建展开语义、
不需要为它维护 state，也不会引入第二套折叠视觉（页面里已有的折叠是 `.wb-fold`，样式更重）。

## 为什么没有做 sticky 结果列

宽面板下"改输入 → 看结果"确实会滚出视野，但结果块高于视口时 sticky 反而会让底部
（带入 AI 协助）永远够不到。权衡后不做：宁可滚动，不要卡住。

## 顺带记下的坑

`styles.ts` 的 CSS 整体在模板字符串里，**注释里出现反引号会提前闭合字面量**。
本轮又踩了一次（写成 `%` 的代码引用），tsc 报的是"左操作数必须是数字"这类**貌似与 CSS 无关**的错误。
写完 CSS 请跑 `test/tokenScope.test.mjs`（有专门一条守卫）。
