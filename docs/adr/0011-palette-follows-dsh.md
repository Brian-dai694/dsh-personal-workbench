# 工作台色系跟随 DSH（强调色 = 宿主品牌色）

**Status:** accepted（2026-10-28，用户要求「工作台和 dsh 统一一个色系」）

## 决定

工作台**不再自带一套配色**。强调色、状态色一律从宿主 DSH 的语义别名派生，明暗两套跟着宿主走：

| 角色 | 工作台令牌 | 来源（宿主别名） |
|---|---|---|
| 强调 | `--wb-accent` | `--dsw-alias-state-business-primary`（deepseek-500/400） |
| 信息 | `--wb-info` | `--dsw-alias-link` |
| 警告 | `--wb-warn` | `--dsw-alias-state-warn-primary` |
| 危险 | `--wb-danger` | `--dsw-alias-state-error-primary` |
| 成功 | `--wb-ok` | `--dsw-alias-state-success-primary` |
| 中性 | `--wb-neutral` | `--dsw-alias-label-tertiary` |

配套三条：

1. **`--wb-accent` 只允许写成 `var(--wb-state-business-primary)`**（原为硬编码墨绿 `color-mix(#2E9B7B 62%, #14493A)`）。换色只改这一行，回退墨绿也只改这一行。
2. **令牌层回退值改成宿主自己的色阶取值**（`entryContract.ts` 的 `TOKENS`）：最坏情况（宿主令牌缺失）退化出来的也是 DSH 同色系，而不是"深黑 #17171a + 16% 黑边框"那一套近似值。
3. **字典数据色也跟随**（`src/shared/palette.ts` 是唯一来源，种子与迁移都从它取值；放在 shared 是因为客户端也要用它做兜底色，而架构约束 R5 只允许客户端 import `client/` 与 `shared/`）：原先紫 `#8B7BE8` / 青 `#16A085` / 紫 `#8E44AD` 混用，宿主调色板里根本没有这些色相。迁移 v35 只改**还停在旧出厂值**的行，用户自己调过的颜色保留。

## Considered Options

- **保留墨绿强调色、只改状态色**：等于继续让"墨绿强调 + 宿主蓝环线"两套强调色并存，用户这条要求就没被满足。
- **只改 CSS、不动字典数据**：任务类型/知识库/点子上的圆点仍是旧私有色板，界面看着还是两套色系。
- **把 DSH 的静态色值抄进工作台 CSS**：DSH 换肤/换主题时会立刻脱节；派生自别名才能自动跟随。
- **连边框强度也抄宿主 `border-l1`（4% 黑）**：那是宿主自己的发丝线口径，但工作台面板是**独立浮层**（白卡叠白底），按 4% 就看不出模块边界 —— 可读性底线（用户在 v1.13.0 明确要求过）优先，边框仍走 `--wb-line*`。

## Consequences

- `test/tokenScope.test.mjs` 新增三条守卫：强调色必须等于宿主别名、五类语义色必须派生自宿主令牌、规则里不得出现任何字面色（`#fff`/`#000` 除外）。想换回自定色，必须连同守卫一起改。
- `test/paletteAlign.test.mjs` 钉住"种子色 == 调色板 == 迁移目标值"，避免再出现"种子写 A、迁移认 B"的静默漂移。
- 深度影响：所有 `--wb-state-business-primary` 的引用（环线、选中、表单聚焦、banner）现在都等于强调色，观感从"绿主蓝辅"变成单一品牌蓝；状态色两档（主色 + `-ink`）保留，`-ink` 改为往宿主深中性里压一档，浅底下对比度 5.4–6.1:1。
- 已存在的库在下次启动时跑迁移 v35，把仍是旧出厂色的字典行对齐到 DSH 色阶；用户在「设置 → 字典管理」里自配的颜色不变。
- 预览与截图：`编程/_palette-preview/`（真实样式表 + 从 app.asar 抽出的 DSH 主题令牌，明暗各一张）。
